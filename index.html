How It Works

🔗 Queue (Linked-List FIFO)

Enforces strict First-Come First-Served fairness. O(1) enqueue at the rear, O(1) dequeue from the front. No student can jump the line.

🗄️ Hash Table (Separate Chaining)

Eliminates O(n) linear search. A polynomial rolling hash maps each Request ID to one of 17 buckets, giving O(1) average-case search. Collisions are resolved via linked-list chaining within each bucket.

🎓 Roll Number Validation

Validates the full Amrita institutional format: CAMPUS.SCHOOL.LEVEL+DEPT+YEAR+SERIAL (e.g. ch.en.u4cce25020). Supports 6 campuses, 8 schools, and 34+ departments.

☁️ Real-Time Cloud Sync

The queue is stored in Cloud Firestore — a real-time database. Requests sync instantly across ALL devices. A student submits from one device, the teacher sees it live on another — no manual refresh needed.
